GenericUI provides **9 Native-First Platform Backends** (`Windows`, `MacOS`, `Gtk`, `Kde`, `Swing`, `Android`, `IOS`, `IPadOS`, `Web`) organized across consolidated core foundation modules (`:common`, `:system`, `:jvm`, `:apple`) and three platform modules ([`desktop`](../desktop/README.md), [`mobile`](../mobile/README.md), and [`web`](../web/README.md)). Every backend implements `:common`'s [`NativeFactory`](../common/src/commonMain/kotlin/com/nexustools/genericui/core/NativeFactory.kt) and symmetrical retained `NativeImpl` peer contracts using **real OS/platform widgets**, while a generated launcher (`<Backend>Launcher`) boots directly into the resolved `@MainAppFragment` (or headless worker entry point when configured).

## 2. 60+Hz Hardware `backdrop-filter` (`StyledButton` & `StyledContainer`)

When an app attaches CSS `backdropFilter` (e.g., `blur(...)`, `saturate(...)`, `brightness(...)`) to any [`StyledButton`](../common/src/commonMain/kotlin/com/nexustools/genericui/component/action/StyledButton.kt) or [`StyledContainer`](../common/src/commonMain/kotlin/com/nexustools/genericui/component/layout/StyledContainer.kt) — including live stage-control HUD overlays — all 9 backends execute hardware-accelerated behind-the-surface sampling at 60+Hz:

| Backend | Hardware Blur Pipeline & Live Video / Stage HUD Support |
| :--- | :--- |
| **Web (`:web`)** | `WebBackdropFilterUtil.applyToElement` sets CSS `backdrop-filter` / `-webkit-backdrop-filter` and promotes GPU compositor layers (`transform: translateZ(0)`, `data-backdrop-compositor-promoted`). |
| **Android (`:mobile`)** | `AndroidHardwareBackdropBlurController` walks up to the nearest backdrop root (`android.R.id.content` or outermost host above `DecorView`), renders strictly pre-order preceding branches (respecting `layerZIndex`), captures live `TextureView` surfaces via `SurfaceTextureListener` (`onSurfaceTextureUpdated` -> `postInvalidateOnAnimation()`), and applies API 31+ `RenderNode`/`RenderEffect.createBlurEffect` (with API 24–30/Robolectric downsampled `Bitmap` + `FastBackdropBlurKernel` fallback). |
| **iOS & iPadOS (`:mobile`)** | `UikitBackdropBlurController` layers a Metal-backed `UIVisualEffectView` (`CABackdropLayer`) + paused `UIViewPropertyAnimator` `fractionComplete` radius scaling + `tintOverlayView` while keeping `hostView.backgroundColor = UIColor.clearColor`. |
| **Windows (`:desktop`)** | `Win32Direct2dBackdropBlurEngine` (`d3d11.dll` + `d2d1.dll` `ID2D1DeviceContext` `CLSID_D2D1GaussianBlur` + `CLSID_D2D1ColorMatrix`, falling back to `FastBackdropBlurKernel`) invoked by `Win32NativeWindowHost.applyBackdropFilterRect`, paired with general CSS `opacity` / `transform` / `z-index` / `pointer-events` node inheritance across `StyledComponent`, `StyledContainer`, `StyledButton`, and `Composite` components (zero component/app fast-paths). |
| **macOS (`:desktop`)** | `MacosSurfaceLayerSupport` + `:apple`'s `AppleStyledSurfaceHelper` mounts native `NSVisualEffectView` (`blendingMode = WithinWindow`, without `CALayer.backgroundFilters`) for `backdrop-filter: blur(...)`, reserving `AppleBackdropFilterController` solely for non-blur W3C filter operations (`requiresFullFilterPipeline`) and offscreen `JestElectricRunner` capture (`MacosNativeWindowHost`), inside retained flipped AppKit `NSView` subviews with general CSS `opacity` / `transform` / `z-index` / `pointer-events` node inheritance across `StyledComponent`, `StyledContainer`, `StyledButton`, and `Composite` components (zero component/app fast-paths). |
| **Linux GTK4 (`:desktop`)** | Toolkit-agnostic `LinuxStyledSurfaceHelper` + `LinuxBackdropFilterController` (`linux/style/`) paired with GTK4 `GtkOverlay`, `GskTransform`, GSK blur effects (`Gtk4DynamicBindings`), and Cairo `FastBackdropBlurKernel` fallback. |
| **Linux KDE (`:desktop`)** | Toolkit-agnostic `LinuxStyledSurfaceHelper` + `LinuxBackdropFilterController` (`linux/style/`) paired with KDE `KWindowEffects::enableBlurBehind` (`KF6` + `Breeze` on Qt6) and `FastBackdropBlurKernel` CPU fallback. |
| **JVM Swing (`:desktop`)** | `SwingHardwareBackdropBlurRenderer` (`:jvm` `JvmBackdropCapturePlanner`) walks to `JRootPane`/outermost `Container`, renders pre-order preceding siblings in reverse Z-order, and runs GPU `VolatileImage` bilinear downsample/upscale ping-pong (`1/2 -> 1/4 -> 1/8`), falling back to `BufferedImage` + `FastBackdropBlurKernel` in headless mode or when pixel color ops are active. |

## 3. Embedded Native Resources, `JniLibraryLoader`, & `ServiceWorker` Matrix

- **Prefix-Free Embedded Resources (`ResourceID`)**: `ResourceID.nativeResourceKey` strips `"gui/"`, `"gui/ext/<cat>/<ext>/"`, and `"app/"` so native backends resolve prefix-free keys without copying loose files beside desktop executables:
  - **Windows**: `WindowsResourceResolverImpl` reads Win32 `RT_RCDATA` resources directly from `<nativeLibraryGroupId>.dll` or the host `.exe` (`FindResourceW`/`LoadResource`/`LockResource`), falling back to legacy numeric resource IDs (`2000..65535`).
  - **macOS**: `MacosResourceResolverImpl` resolves Mach-O `__TEXT,__const` lookup functions (`genericui_res_lookup_<group>` / `genericui_res_lookup_app`) via `dlsym` inside the signed Mach-O binary or `Contents/Frameworks/lib<group>.dylib`; `.app/Contents/Resources/` contains only `icon.icns` (and optional `MoltenVK_icd.json`) with zero loose `gui/` or `app/` folders.
  - **Linux (`Gtk` & `Kde`)**: `LinuxResourceResolverImpl` resolves ELF `.rodata` `genericui_res_lookup_*` / `genericui_res_lookup_app` symbols via `dlsym` inside the running ELF executable or `lib<group>.so` (strictly keeping `libgenericui-gtk.so` and `libgenericui-kde.so` isolated).
  - **JVM (`Swing` & `Android`)**: [`JniLibraryLoader`](../jvm/src/jvmSharedMain/kotlin/com/nexustools/genericui/jvm/JniLibraryLoader.kt) tries `System.loadLibrary(...)` first (Android `lib/<abi>/` with 16KB ELF/ZIP alignment & `java.library.path`) and extracts `META-INF/native/<os>-<arch>/` native libraries from Swing JARs on demand.
- **`ServiceWorker`, Tray, Autostart, & `openWindowOnLaunch = false`**:
  - **Desktop (`Windows`, `MacOS`, `Gtk`, `Kde`)**: Dedicated secondary executable `serviceworker.exe` / `serviceworker` (`Contents/MacOS/serviceworker` on macOS) with OS singleton locks (`CreateMutexW`, `flock`, `fcntl`), loopback `127.0.0.1:0` IPC + 32-byte hex auth token, OS autostart (`Startup/*.lnk`, `LaunchAgents/*.plist`, XDG `autostart/*.desktop`), and headless tray event loops (`WindowsHeadlessTrayLoop`, macOS `NSApplicationActivationPolicyAccessory` + unwrapped embedded tray icon, GTK `org.kde.StatusNotifierItem`, KDE `KStatusNotifierItem` D-Bus tray).
  - **Swing (`jvm`)**: `GeneratedSwingServiceWorkerMain` compiled into the same Swing JAR using `FileChannel.tryLock()` + `SwingSystemTrayImpl` headless loop wait.
  - **Android**: `AndroidExtensionRuntimeBridge`, `GeneratedAndroidServiceWorkerService`, `AndroidServiceWorkerController`, `ServiceCompat.startForeground` ongoing notification (default `"Stop"` button + `updateNotificationText` + `extendNotificationActions` / `replaceNotificationActions`), `AndroidServiceWorkerBinder` IPC, and conditional `BOOT_COMPLETED` receiver when `autostart = true`.
  - **iOS & iPadOS**: `ServiceWorkerExtension.isSupported == false` (`AppleMobileServiceWorkerRuntime`) — zero simulation, `@MainServiceWorker` never instantiated.
  - **Web**: Unified root `./serviceworker.js` registered by `loader.js` after resource preload completes, single-copy `gui/`/`gui/ext/<extcat>/<ext>/`/`app/`, `self.GenericUiServiceWorker` (`WebWorkerGlobalBridge` / `WebServiceWorkerClientBridge`), and dual `${appname}.sw.wasm` + `${appname}.sw.js` worker bundles.

## 4. Retained Native System Controls, Strictly `Button`-Only `BootstrapType`, `style.scss`-First Rules, & Style Restraints

1. **`BootstrapType.NONE` Default & Non-`Button` Controls**: Native system backends mount **100% unmodified genuine OS system controls** (Win32 `ComCtl32 v6` `HWND`s, AppKit `NSControl`, GTK4/Libadwaita `GtkWidget*`, KDE `KF6` + `Breeze` alien `QWidget*`, Swing system L&F, Material/AppCompat, UIKit `UIControl`) for `BootstrapType.NONE && !outline` and all non-`Button` controls (with form subclasses marking `data-control-variant` for specialized native pickers/fields).
2. **Strictly `Button`-Only Control `BootstrapType` + Native Control Tinting vs. Swing Fallback**: Among control components, **ONLY `Button` and subclasses of `Button`** (`Button`, `IconButton`, `ToggleButton`, `FloatingActionButton`, `StyledButton`) support `BootstrapType`. All native desktop and mobile backends retain genuine OS button controls in both default (`(type == null || type == BootstrapType.NONE) && !outline`) and semantic Bootstrap modes: macOS uses genuine `NSButton` (`bezelColor`, `hasDestructiveAction`, `bordered`, `showsBorderOnlyWhileMouseInside`, `contentTintColor`); GTK uses genuine `GtkButton` with Libadwaita/GTK CSS classes and a theme-derived `GtkCssProvider`; KDE uses genuine `QPushButton` with `setFlat` and per-widget `QPalette` styled by `Breeze`; Windows keeps genuine `"Button"` (`WC_BUTTON`) child `HWND`s (`CDRF_DODEFAULT` in `NM_CUSTOMDRAW` when unmodified, `CDDS_PREPAINT` -> `CDRF_SKIPDEFAULT` where UxTheme `BP_PUSHBUTTON` lacks a color-tint API); iOS/iPadOS uses genuine `UIButton` with native `UIButtonConfiguration` (`filled`/`plain`, `baseBackgroundColor`, `baseForegroundColor`, `strokeColor`); and Android uses genuine `AppCompatButton` with native `backgroundTintList` / `RippleDrawable` + `GradientDrawable` (no CPU bitmap pixel-tinting in `onDraw`). Only Swing continues using `SwingControlTintRenderUtil` / `JvmControlTintPixelUtil` where standard Java Look-and-Feels ignore button background tinting. **`DropdownButton`, `SplitDropdownButton`, `ProgressBar`, `Spinner`, `StyledSlider`, `Composite`, and all other non-`Button` control components MUST NOT support `BootstrapType`.**
3. **Bootstrap-Specific Non-Control Classes**: `Badge`, `Alert`, `Banner`, `Toast`, `Card`, `ListGroup`, `ListGroupItem`, `Jumbotron`, and `Well` DO support `BootstrapType` (`type`, `backgroundType`, `textColorType`, `borderType`) across all **9 backends**, mounting custom native semantic widgets styled via `:system`'s `SemanticSurfaceStyleResolver` (`SemanticSurfacePaintSpec`).
4. **`style.scss`-First Discipline & Consumer-App-Only `theme.scss` Compilation**: Static visuals, interactive state visuals (`:hover`, `:focus`, `:active`, `:disabled`), layouts (`position`, `top`, `transform`, `z-index`, `pointer-events`, `cursor`), and `@keyframes` transitions (such as `.hidden` fading overlays driven by `SystemCssAnimationController` / `Animator` on `:system` and native CSS on `:web`) live in `style.scss` / raw upstream `theme.scss` templates (packaged uncompiled inside library `META-INF/genericui/themes/<scopeId>.scss` + `module-resources/<scopeId>.json`, never compiled/integrated into library artifacts, and compiled solely by the consumer app's `:gradle-plugin` build into `GenericUiGeneratedThemeStyleSheet` / `gui/genericui-theme.css`). Kotlin only updates runtime-dynamic percentage values, and backends / `:system` enforce **zero** class/id/app-specific fast-paths.
5. **Typography vs. Aesthetic Style Restraints**:
   - **Text elements** (`Label`, `Text`, `Heading`, `Blockquote`, `CodeBlock`, `MarkdownView`) honor typography and color styles on all 9 backends.
   - **Non-`Button` controls & standard containers** (`DropdownButton`, `SplitDropdownButton`, `CheckBox`, `TextField`, `Select`, `ProgressBar`, `Spinner`, `Container`, etc.) do not support `BootstrapType` and silently ignore aesthetic skinning (`backgroundColor`, `borderRadius`, `boxShadow`) on all 8 system backends. Use **`Button` subclasses** for `BootstrapType`, **`Badge`/`Alert`/`Banner`/`Toast`/`Card`/`ListGroup`/`ListGroupItem`/`Jumbotron`/`Well`** for custom Bootstrap semantic surfaces, or **`StyledComponent`**, **`StyledContainer`**, **`StyledButton`**, **`Composite`** / **`StyledSlider`** (uniformly realized via `StyledContainerNativeImpl` / `StyledComponentNativeImpl` with zero custom `*NativeImpl`; `Composite`/`StyledSlider` do NOT support `BootstrapType`), or `:extensions:ui:alien` for full custom chrome (including 60+Hz 10-op `backdrop-filter` and proximal `position: relative` / `Window` containing-block parity).

## 5. Strict User CSS Class Isolation, `CssCustomCursor`, & Precompiled `.scss`

- **User CSS Classes**: User classes (`addClass`, `removeClass`, `hasClass`, `getClasses()`, `getClass()`, `setClass`) remain strictly isolated from `ComponentBootstrap` enums (`WebDomElement.userClassList` vs. `enumClassList` on `:web`; `styleSnapshot.customClasses` on system backends).
- **`CssCustomCursor`**: Translates PNG/SVG `ResourceID`s, inline SVG, and `ImageBuffer`s with `(hotspotX, hotspotY)` into Windows `.cur` (`WindowsCurCodec`), macOS Retina `@1x`/`@2x` `NSCursor` (`MacosCursorTranslator`), iPadOS `UIPointerInteraction` (`IpadosPointerAndKeyboardInstaller`), GTK4 `GdkCursor`, KDE `QCursor`, Swing `Toolkit.createCustomCursor`, and CSS `url(...)`.
- **`PrecompiledStyleSheet`**: `.scss` assets compile at build time (`compileGenericUiSass`) into zero-parse `Resource.style.<name>` (`PrecompiledStyleSheet`) on all 8 system backends and `.css` bundles (`WebStyleSheetManager`) on `:web`.

## 6. Selecting Backends & Registered Build Tasks

```kotlin
genericui {
    backends {
        all() // Enables all 9 backends: windows, macos, gtk, kde, swing, android, ios, ipados, web
        // allExceptSwing(), allDesktop(), allDesktopExceptSwing(), allMobile(), ios(), ipados()
    }
}
```

| Platform Backend | Development Task | Production Task |
| :--- | :--- | :--- |
| **Windows** | `./gradlew developmentWindows` | `./gradlew productionWindows` |
| **macOS** | `./gradlew developmentMac` (`developmentMacos`) | `./gradlew productionMac` (`productionMacos`) |
| **Linux GTK4** | `./gradlew developmentLinuxGtk` | `./gradlew productionLinuxGtk` |
| **Linux KDE** | `./gradlew developmentLinuxKde` | `./gradlew productionLinuxKde` |
| **JVM Swing** | `./gradlew developmentSwing` | `./gradlew productionSwing` |
| **Android** | `./gradlew developmentAndroid` | `./gradlew productionAndroid` |
| **iOS (iPhone)** | `./gradlew developmentIos` | `./gradlew productionIos` |
| **iPadOS (iPad)** | `./gradlew developmentIpados` | `./gradlew productionIpados` |
| **Web (`wasmJs` + `js`)** | `./gradlew developmentWeb` | `./gradlew productionWeb` |

Native desktop builds link shared libraries per layer (`libgenericui.{dylib,so}` / `genericui.dll`, `libgenericui-{macos,gtk,kde}.*` / `genericui-windows.dll`, and enabled `genericui-ext-*` / `njs` / `genericui-tests`) staged in `<App>.app/Contents/Frameworks/` on macOS and flat alongside the executables (`main` + optional `serviceworker`) on Linux and Windows; Swing JARs, Android APKs (16KB page-aligned `.so` payloads), iOS/iPadOS frameworks, and Web bundles remain integrated in their application packages.
